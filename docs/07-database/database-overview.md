# Database Overview

> **Audience:** Developers, operators · **Last verified:** 2026-11-30 against commit `d1296b1`
> **Related:** [Database schema](database-schema.md), [Tables and columns](tables-and-columns.md), [Entity relationships](entity-relationships.md), [Migrations](migrations.md), [Backup and restore](backup-and-restore.md), [Database architecture](../04-architecture/database-architecture.md)

The Hub stores everything in one relational database. Development and the default `.env.example` use SQLite. The live site on Render uses PostgreSQL. The schema has 30 tables (21 application tables and 9 framework tables), built by 17 migration files, and is accessed only through Eloquent models.

## Engines

| Environment | Engine | How it is chosen |
| --- | --- | --- |
| Local development | SQLite file `database/database.sqlite` | `DB_CONNECTION=sqlite` in `.env.example`. `config/database.php` defaults to `sqlite`. |
| Automated tests (CI job "Tests (sqlite)") | SQLite in memory | `DB_DATABASE=:memory:` in `ci.yml` |
| Automated tests (CI job "Tests (pgsql)") | PostgreSQL 16 service container | `DB_CONNECTION=pgsql` and `DB_URL` in `ci.yml` |
| Live site (Render) | PostgreSQL, free plan | `DB_CONNECTION=pgsql`, `DB_URL` from the Render database `uew-innovation-hub-db` (`render.yaml`) |
| Vercel (alternative) | External PostgreSQL through `DB_URL`, set in the Vercel project settings (`vercel.json` sets no database variables). `api/index.php` says persistent data must live in an external database. | `api/index.php` and `vercel.json` |

`config/database.php` also defines `mysql`, `mariadb` and `sqlsrv` connections (Laravel defaults). Only SQLite and PostgreSQL are used and tested. The legacy system used MySQL; see below.

Models avoid engine-specific SQL. Two places branch on the driver: `Project::yearExpression()` (`strftime` on SQLite, `EXTRACT(YEAR ...)` on PostgreSQL, `YEAR()` otherwise) and the `Searchable` trait, which uses `ilike` on PostgreSQL and `like` elsewhere (API v2 `PartnerController` repeats the same switch). See [database-troubleshooting.md](database-troubleshooting.md) for the differences between the two engines.

## Conventions in this schema

| Convention | Detail |
| --- | --- |
| Primary keys | `id` (auto-increment big integer) on most tables. String keys on `settings.key`, `email_templates.key`, `cache.key`, `sessions.id`, `password_reset_tokens.email`. UUID string on `notifications.id`. |
| Enums | Stored as short `varchar` strings and cast to PHP backed enums in the models (`app/Enums/`). There are no database `ENUM` types. Three columns have a `CHECK` constraint (`projects.status`, `posts.type`, `grant_applications.status`); every other status and type column accepts any string. See [tables-and-columns.md](tables-and-columns.md) for allowed values. |
| Booleans | `tinyint` (SQLite) or `boolean` (PostgreSQL), cast to `boolean` in models. |
| JSON | Columns created with `->json()` (PostgreSQL `json`, SQLite text). Cast to `array` in models. |
| Money | `decimal(12,2)` for grants and funding, `decimal(14,2)` for report budgets. Currency is not stored. The API and UI assume GHS. |
| Slugs | `slug` is unique on `projects`, `publications`, `posts`, `programs`, `albums`, `pages`. Generated by the `HasUniqueSlug` trait on `projects`, `publications`, `posts`, `programs` and `albums`. `pages` slugs are entered in the form or set by `PageSeeder`. |
| References | `reference` (applications, progress reports) and `reference_no` (`grant_applications`) are unique business identifiers. Applications and progress reports use `reference` as their route key. |
| Soft deletes | `deleted_at` on `projects`, `publications`, `posts`, `programs`, `grant_applications`. See [data-retention.md](data-retention.md). |
| Foreign keys | Declared with `constrained()`. Most user links use `ON DELETE SET NULL` so history survives account deletion. Ownership links use `CASCADE`. See [indexes-and-constraints.md](indexes-and-constraints.md). |
| Timestamps | `created_at` and `updated_at` on nearly every table. |

## Data access rules

- All application code uses Eloquent or the query builder with bound parameters. There is no raw user input in SQL. The raw fragments that exist (`Project::yearExpression()`, `Album::scopeLatestEvents()`, `MetricsService`) contain no user input.
- Mass assignment is controlled with `$fillable`. Models for workflow records (`ProgramApplication`, `ProgressReport`, `Achievement`, `ApplicationMessage`, `VerificationCode`) have an empty `$fillable` and are written with `forceFill` in services.
- `User::$hidden` hides `password` and `remember_token`. `VerificationCode::$hidden` hides `code_hash`.

## Legacy data

The old system (`legacy/`, MySQL, procedural PHP) is kept for reference. Its project and publication records were mapped into the current schema with the `legacy_id` columns on `projects` and `publications` (indexed, not unique). `DemoContentSeeder` recreates the sample records. Legacy PDFs are copied onto the documents disk by `php artisan hub:import-documents`. The one-off import of production legacy rows is not a migration or command in this repository.

> **Requires confirmation:** how the legacy MySQL rows were originally migrated (a one-off script is not present in `database/` or `app/Console/Commands/`).

## Schema findings

| Finding | Where |
| --- | --- |
| `users.role` has database default `officer`, but the `User` model attribute default is `viewer`. Rows created through Eloquent get `viewer`. | `0001_01_01_000000_create_users_table.php`, `User::$attributes` |
| `grant_applications.status` has two overlapping indexes: `(status)` and `(status, created_at)`. (`reference_no` has only the unique index; Laravel skips the second index in `unique()->index()`.) | `2026_11_23_000007`, `2026_11_24_000001` |
| `albums.cover_photo_id` is an unsigned big integer with no foreign key to `album_photos`. Integrity is kept by `GalleryService`. | `2026_11_30_000001` |
| `password_reset_tokens` is created by Laravel's default migration. Password reset uses `verification_codes` (purpose `reset_password`), so the table appears unused. | `0001_01_01_000000` |
| `sessions.user_id` is indexed but has no foreign key. | `0001_01_01_000000` |
| Only three status and type columns have a CHECK constraint. The rest accept any string. | [tables-and-columns.md](tables-and-columns.md#enum-columns-with-a-check-constraint) |
| The duplicate "strong `SEED_PASSWORD`" guard in `DatabaseSeeder` was removed in commit `d1296b1`. | `database/seeders/DatabaseSeeder.php` |
| No scheduled pruning: sessions are swept by Laravel, but codes, notifications, failed jobs and the audit log are never removed. | [data-retention.md](data-retention.md) |
| Several foreign key columns have no index (for example program_applications.user_id), and updated_at is not indexed although API v2 filters on it. | [indexes-and-constraints.md](indexes-and-constraints.md) |
