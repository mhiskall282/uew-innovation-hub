This is the canonical column reference for all 30 tables: type, nullability, default, purpose, allowed values for enum-like columns, and which code writes the privileged columns. Facts come from a schema dump of a fresh migration run (see [tables-and-columns](../07-database/tables-and-columns.md)) (generated by running every migration on SQLite), the migrations in [`database/migrations/`](../../database/migrations), the models in [`app/Models/`](../../app/Models) and the enums in [`app/Enums/`](../../app/Enums). Indexes and foreign keys are listed in [indexes-and-constraints.md](indexes-and-constraints.md).

## How to read these tables

- **Type** is the Laravel column type. On SQLite it becomes `integer`, `varchar`, `text`, `numeric`, `datetime` or `tinyint`. On PostgreSQL, Laravel creates `bigint`, `varchar(n)`, `text`, `numeric(p,s)`, `timestamp(0) without time zone`, `boolean` and `json`. `unsignedTinyInteger` becomes `smallint`. PostgreSQL types were not dumped for this page; they follow Laravel's PostgreSQL grammar.
- **Null** is `yes` when the column accepts `NULL`. **Default** is the database default. The Eloquent model can set a different default through `$attributes`; this is called out where they differ.
- Enum-like columns are plain `varchar`. The database does not restrict the values, with three exceptions described in [Enum columns with a CHECK constraint](#enum-columns-with-a-check-constraint). The PHP enum is the source of truth.
- Every table with `created_at` and `updated_at` uses `timestamps()` (both nullable). They are set by Eloquent and are not repeated in the tables below.
- "Written by" names the code that sets the column. Columns that are mass assignable through `$fillable` are marked "form input". Workflow columns are written with `forceFill` or direct assignment in a service so that request input cannot set them.

## Enum columns with a CHECK constraint

Three columns were created with `$table->enum()`. SQLite and PostgreSQL both add a `CHECK (col IN (...))` constraint, so the database rejects other values. Adding a new value to the PHP enum needs a migration that rebuilds the constraint, which is awkward on SQLite. See [migrations.md](migrations.md).

| Column | Allowed by the constraint | PHP enum |
| --- | --- | --- |
| `projects.status` | `active`, `completed`, `suspended`, `pending` | `ProjectStatus` (same four values) |
| `posts.type` | `news`, `blog`, `announcement` | `PostType` (same three values) |
| `grant_applications.status` | `submitted`, `under_review`, `shortlisted`, `approved`, `rejected` | `GrantStatus` (same five values) |

All other status and type columns are unconstrained `varchar`.

## Audit

### `activity_logs`

Model: [`ActivityLog`](../../app/Models/ActivityLog.php). Written only through `AuditLogger::record`, which takes the actor and IP from the server-side session and request. The table is append-only by convention: no code updates or deletes rows, and the database does not enforce it.

| Column | Type | Null | Default | Purpose and values | Written by |
| --- | --- | --- | --- | --- | --- |
| `id` | bigint | no | | Primary key. The audit screen orders by it. | Database |
| `user_id` | bigint, FK to `users` | yes | | Actor. `SET NULL` on delete, so history survives account deletion. | `AuditLogger` |
| `action` | varchar(255), indexed | no | | Dotted name such as `project.created` or `auth.password_reset`. The first segment is the "area" used by the audit filter (18 areas, `AuditLogController::AREAS`). | `AuditLogger` |
| `description` | text | no | | Human sentence. | `AuditLogger` |
| `ip_address` | varchar(45) | yes | | Client IP. | `AuditLogger` |
| `properties` | json | yes | | Extra context, usually a field diff. Passwords are recorded as `changed`, never as values. | `AuditLogger` |
| `subject_type` | varchar(255) | yes | | Morph class of the record the action concerned. | `AuditLogger` |
| `subject_id` | bigint unsigned | yes | | Id of that record. No foreign key, so rows outlive the subject. | `AuditLogger` |

`subject_type` and `subject_id` are a polymorphic pair created with `nullableMorphs('subject')`. The application does not define a morph map, so `subject_type` holds the full class name, for example `App\Models\Project`. Renaming or moving a model class orphans the history.
