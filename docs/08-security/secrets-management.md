# Secrets Management

> **Audience:** operators, developers · **Last verified:** 2026-11-30 against commit `9f3bdee`
> **Related:** [Secure configuration](secure-configuration.md), [Security incident response](security-incident-response.md), [Environment configuration](../09-deployment-and-operations/environment-configuration.md), [Dependency security](dependency-security.md)

This page lists every secret the system uses, where it lives, who can read it, how it is protected from the repository, and how to rotate it. No secret value appears in this documentation.

## Inventory

| Secret | Variable or storage | Where it is set | Used for |
| --- | --- | --- | --- |
| Application key | `APP_KEY` | Render (`generateValue: true`) or `php artisan key:generate --show` | Encrypts cookies, `Crypt` values (SMTP password), signs URLs |
| Database credentials | `DB_URL` | Render, from the managed database (`fromDatabase` in `render.yaml`) | PostgreSQL connection |
| First administrator password | `ADMIN_PASSWORD` | Render (`sync: false`) | `hub:create-admin` on boot |
| Demo account password | `SEED_PASSWORD` | Render (`sync: false`) | `DemoContentSeeder`, `hub:secure-demo-accounts` |
| Object storage keys | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_BUCKET`, `AWS_ENDPOINT` | Render (`sync: false`) | S3/R2 documents and gallery disks |
| SMTP environment credentials | `MAIL_USERNAME`, `MAIL_PASSWORD` | Render | Default mail transport |
| SMTP workspace credentials | `settings.mail_password` | Site settings page (Hub Director) | Overrides the environment transport when mailer is `smtp` |
| Redis password | `REDIS_PASSWORD` | `.env.example` placeholder | Not used by the shipped configuration (sessions, cache and queue use the database) |

## Rules the repository follows

- `.env` is git-ignored (`.gitignore`: `.env`, `.env.backup`, `.env.production`, `.env.*.local`). `.dockerignore` and `.vercelignore` also exist. Documentation must never open or quote `.env`.
- `.env.example` holds placeholders only. It does contain `SEED_PASSWORD=password`, a deliberately weak local default. The code refuses to seed demo accounts in production unless `SEED_PASSWORD` is strong (`DatabaseSeeder`, `SecureDemoAccounts::isStrong`: 12+ characters, mixed case, a number).
- `render.yaml` marks every secret `sync: false` so values are entered in the Render dashboard, not committed. `APP_KEY` is generated by Render.
- Apache denies dotfiles and serves only `public/`, so `.env` is not web-reachable. A black-box check recorded in `docs/security.md` confirmed `.env` and `.git` are blocked on the live site.
- `.git` history: `scripts/security-scan.ps1` searches all commits for private keys, GitHub tokens, AWS key IDs, `MAIL_PASSWORD=` and `APP_KEY=base64:` patterns, and for the tester password. The handover report ([`FINAL_PROJECT_HANDOVER_REPORT.md`](../audit/FINAL_PROJECT_HANDOVER_REPORT.md), finding F-02) records zero hits in tracked files and the tester password still present in history. The script is re-runnable; this documentation did not re-run it.

## The tester password in commit `87df882`

A password used for testing was committed in `87df882` ("Secure demo accounts..."). The history was not rewritten, and the repository is public.

- Treat that password as public. Do not use it, or anything derived from it, on any account.
- Confirm that no deployed account still uses it. The entrypoint's `hub:secure-demo-accounts` replaces known weak passwords with `SEED_PASSWORD`, but it only knows the `WEAK` list (`password`, `secret`, `12345678`, `password123`, `admin`, `changeme`). It does not know the tester password. **Requires confirmation:** that the account which used it was rotated.
- Rewriting history (`git filter-repo`) is possible but breaks every clone and open pull request. Rotating the password is the necessary step; rewriting is optional.
- The `legacy/` folder holds the old system's hard-coded local database credentials. `docs/security.md` advises treating them as compromised.

## Encryption of secrets inside the application

- `settings.mail_password` is stored with `Crypt::encryptString` (AES-256-CBC with `APP_KEY`, via Laravel). The audit log records `changed`, never the value. The browser never receives it (`MailSettings::hasPassword()` returns only a boolean).
- Changing `APP_KEY` makes the stored SMTP password undecryptable: `MailSettings::password()` catches the exception and returns `null`, so SMTP authentication fails until the Hub Director re-enters the password.
- Other `settings` values are plain text.

## Rotation procedures

> **Warning:** do these during a quiet period. Several invalidate sessions or links.

| Secret | Steps | Side effects |
| --- | --- | --- |
| `APP_KEY` | Generate: `php artisan key:generate --show` (PowerShell and bash). Set in Render, redeploy | All sessions and remember-me cookies stop working. Signed links (verification, reset, unsubscribe) stop validating, including those already e-mailed. Encrypted `settings.mail_password` must be re-entered |
| `SEED_PASSWORD`, `ADMIN_PASSWORD` | Change in Render, redeploy. `hub:secure-demo-accounts` re-applies `SEED_PASSWORD` only to accounts that still hold a default password; `hub:create-admin` is idempotent and does not overwrite an existing administrator's password | Change real accounts through the workspace |
| Database password | Rotate in the Render database settings, then redeploy so `DB_URL` refreshes | Brief downtime |
| S3/R2 keys | Create a new key pair in the provider, update `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`, redeploy, then delete the old key | None if done in that order |
| SMTP (environment) | Change `MAIL_PASSWORD` in Render, redeploy | Mail fails until redeploy finishes |
| SMTP (workspace) | Site settings > E-mail, enter the new password, save. The app runs `queue:restart` | None |

Run these at least when a person with dashboard access leaves, and after any suspected leak. Rotation on a schedule is Recommended, not implemented.

## Checks

- Run `scripts/security-scan.ps1` (read-only, PowerShell) before a release. It checks tracked files for secrets, history for secrets, files that must never be tracked, `.env` ignored, and production config.
- CI does not scan for secrets. See [dependency security](dependency-security.md).

## Gaps

| Gap | Note |
| --- | --- |
| No automated secret scanning in CI | `ci.yml` has no gitleaks, trufflehog or GitHub secret scanning step. GitHub's own secret scanning for public repositories may be on at repository level (**Requires confirmation**, repository settings are not in the code) |
| Tester password remains in history | Rotate and confirm |
| `hub:create-admin` prints a generated password once when `ADMIN_PASSWORD` is empty | On Render that output lands in the deploy log. Set `ADMIN_PASSWORD` and change it after first sign-in |
| No rotation schedule | Document an owner and interval |
| No secret manager beyond Render environment variables | Acceptable at this size |
